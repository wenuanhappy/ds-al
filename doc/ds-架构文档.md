# 数据结构可视化学习平台 - 架构文档
## 一、项目背景与目标
### 1.1 项目定位
数据结构可视化学习平台是一款“学习 + 社交 + 智能辅助”三位一体的综合性 Web 学习工具，核心目标是通过**交互式可视化**降低数据结构与算法的理解门槛，通过**社交协作**构建学习社区，通过**AI 智能辅助**提供个性化答疑，最终助力用户高效掌握数据结构与算法知识。

### 1.2 核心约束与诉求
- **功能约束**：需支持课程学习、可视化演示、练习模式、好友互动、评论交流、AI 答疑等全链路场景；
- **非功能诉求**：前端页面高性能（首屏加载快、可视化流畅）、后端接口高可用（稳定响应、异常兼容）、跨端兼容（主流浏览器适配）、可扩展性（支持 AI 模型迭代、课程内容新增）；
- **协作诉求**：前后端分离架构，需明确模块边界与接口规范，支撑多角色（前端/后端/测试/运维）协作。

## 二、整体架构概览
### 2.1 架构分层（前后端分离）
采用经典的“前端应用层 → 接口网关层 → 后端服务层 → 数据存储层”四层架构，配合第三方服务扩展能力：
```
┌───────────────────────── 前端应用层 ──────────────────────────┐
│  Vue 3 + Vite 构建的 SPA 应用（可视化/社交/AI 助手/课程模块）  │
└───────────────────────────────┬───────────────────────────────┘
                                │ HTTP/HTTPS（RESTful API）
┌───────────────────────────────▼───────────────────────────────┐
│  接口网关层（可选，生产环境可集成 Nginx 反向代理/负载均衡）    │
└───────────────────────────────┬───────────────────────────────┘
                                │
┌───────────────────────────────▼───────────────────────────────┐
│  后端服务层（Spring Boot 3.x 微服务风格，按领域模块化）        │
│  ├─ 用户服务（认证/个人信息）  ├─ 社交服务（好友/评论）        │
│  ├─ 学习服务（课程/练习/记录） ├─ 工具服务（操作记录/数据库测试）│
│  └─ 公共服务（全局异常/跨域/文档）                            │
└───────────────────────────────┬───────────────────────────────┘
                                │ JDBC/MyBatis-Plus
┌───────────────────────────────▼───────────────────────────────┐
│  数据存储层（MySQL 8.0，按业务模块分表设计）                  │
└───────────────────────────────────────────────────────────────┘
        ▲                          ▲
        │                          │
┌───────┴───────┐          ┌───────┴───────┐
│ 第三方服务层  │          │ 静态资源层    │
│ - AI 模型（GPT-4V/Coze） │ - 前端打包资源 │
│ - 可视化脚本库 │ - 算法演示脚本        │
└───────────────┘          └───────────────┘
```

### 2.2 核心架构特点
- **前后端解耦**：通过标准化 RESTful API 通信，前端聚焦用户体验，后端聚焦业务逻辑与数据安全；
- **模块化设计**：前后端均按“领域边界”划分模块（如用户、社交、学习），降低模块间耦合；
- **可扩展能力**：支持独立扩展 AI 服务、新增课程模块，无需重构核心架构；
- **可视化与业务分离**：前端可视化脚本（如算法动画）独立封装，通过按需加载提升性能。

## 三、技术栈选型与决策依据
### 3.1 核心技术栈清单
| 架构层       | 技术选型                                  | 版本          | 决策依据                                                                 |
|--------------|-------------------------------------------|---------------|--------------------------------------------------------------------------|
| 前端应用层   | 核心框架                                  | Vue 3 (Composition API) | 性能优于 Vue 2，组合式 API 便于复杂逻辑复用（如可视化控制器、AI 交互）     |
|              | 构建工具                                  | Vite          | 热更新快、打包效率高，支持精细化分包，适配前端性能优化需求               |
|              | 状态管理                                  | Pinia         | 轻量、TypeScript 友好，适配 Vue 3 生态，比 Vuex 更易维护                 |
|              |  UI 组件库                                | Element Plus + View UI Plus | 组件丰富、交互成熟，覆盖表单、弹窗、导航等高频场景，降低开发成本         |
|              | 可视化支撑                                | 自定义脚本 + TailwindCSS | 原子化 CSS 便于样式调整，自定义脚本适配算法可视化的灵活需求               |
| 后端服务层   | 核心框架                                  | Spring Boot 3.x | 成熟稳定、生态完善，支持 SpringDoc OpenAPI 自动生成接口文档，适配团队技术栈 |
|              | 数据访问                                  | MyBatis-Plus  | 简化 CRUD 操作，支持分页、条件查询，提升后端开发效率                     |
|              | 文档工具                                  | SpringDoc OpenAPI | 与 Spring Boot 无缝集成，自动生成 Swagger UI，降低前后端协作成本          |
|              | 安全工具                                  | Spring Security Crypto | 提供密码加密能力，保障用户数据安全                                       |
| 数据存储层   | 数据库                                    | MySQL 8.0     | 开源稳定、社区活跃，支持复杂查询与事务，适配学习平台的数据存储需求         |
| 第三方服务   | AI 模型                                   | GPT-4V / Coze | 支持多模态交互（文本+图片），适配算法答疑的专业场景                       |
| 部署工具     | 容器化                                    | Docker + Docker Compose | 环境一致性强，支持一键部署前后端+数据库，降低运维成本                     |

### 3.2 放弃方案说明
- 前端放弃 Vue 2 + Webpack：Vue 3 性能更优，Vite 构建速度远超 Webpack，适配可视化脚本的快速迭代需求；
- 后端放弃 Spring Cloud 微服务：项目规模未达超大规模，Spring Boot 单体架构（模块化设计）足够支撑，降低部署复杂度；
- 数据库放弃 MongoDB：学习平台以结构化数据（用户、课程、记录）为主，MySQL 关系型数据库更适配数据关联查询需求。

## 四、核心模块与边界
### 4.1 前端核心模块
| 模块名称       | 核心职责                                  | 依赖后端接口                | 模块边界（禁止跨模块直接调用）       |
|----------------|-------------------------------------------|-----------------------------|--------------------------------------|
| 登录认证模块   | 注册/登录、路由守卫、用户状态管理          | /api/login、/api/register   | 仅向其他模块提供“用户登录状态”查询    |
| 课程与练习模块 | 课程展示、算法可视化、练习模式交互        | /api/me/studyrecord/*       | 不直接操作社交相关数据（好友/评论）   |
| 社交互动模块   | 好友申请/管理、评论发布/互动              | /api/friends/*、/api/comments/* | 不直接操作课程学习数据                |
| AI 助手模块    | 多模型切换、文本/图片提问、回答展示       | 第三方 AI API（独立封装）   | 仅依赖用户状态模块获取登录信息        |
| 个人中心模块   | 个人信息展示/编辑、学习记录查询            | /api/me/space、/api/me/studyrecord/* | 不直接修改其他模块的业务数据          |

### 4.2 后端核心模块
| 模块名称（Controller 层面）       | 核心职责                                  | 依赖服务/DAO                | 模块边界                              |
|-----------------------------------|-------------------------------------------|-----------------------------|---------------------------------------|

| 好友模块（Friend*/FriendRequest*） | 好友申请、列表查询、关系管理              | FriendService、FriendDao    | 仅操作好友关系表，不跨模块修改用户信息 |

## 六、非功能设计
### 6.1 性能优化
- **前端**：
  - 路由懒加载（动态导入课程/练习页面）；
  - 算法脚本按需加载（ScriptLoader 工具类，仅进入对应页面时加载）；
  - 静态资源缓存（Nginx 配置 7 天缓存，减少重复请求）；
  - 打包优化（Terser 压缩代码、删除 console，按模块拆分 chunk）。
- **后端**：
  - 数据库索引优化（用户ID、课程ID等关键字段建索引）；
  - 分页查询（评论、学习记录等列表接口支持分页，避免大数据量返回）；
  - 缓存策略（好友申请暂存缓存，提升响应速度）。

### 6.2 安全设计
- **接口安全**：
  - 登录态校验（前端存储用户状态，后端接口隐含登录态验证）；
  - 密码加密（Spring Security Crypto 加密存储，避免明文泄露）；
  - 跨域配置（MyCorsFilter 限制允许的 Origin，防止跨域攻击）。
- **数据安全**：
  - 敏感字段脱敏（返回用户信息时隐藏手机号/邮箱部分字符，可选）；
  - 异常防护（全局异常处理器捕获参数错误、业务异常，避免暴露服务器信息）。

### 6.3 可扩展性设计
- **模块扩展**：前后端均采用模块化设计，新增课程类型（如“哈希表”）时，仅需新增对应前端组件与后端接口，无需修改核心架构；
- **AI 模型扩展**：前端封装 AI 接口调用工具（coze.ts/gpt.ts），新增 AI 模型时仅需扩展工具类，不影响业务逻辑；
- **部署扩展**：支持 Docker Compose 集群部署，可独立扩展后端服务实例或数据库主从分离。

### 6.4 兼容性设计
- 前端适配主流浏览器（Chrome、Firefox、Edge），支持响应式布局（适配电脑/平板设备）；
- 后端接口兼容不同版本的前端请求，统一响应格式（Result<T>），降低版本迭代的兼容性风险。

## 七、部署架构
### 7.1 开发环境部署（单机）
```
┌──────────────────────────────── 本地环境 ────────────────────────────────┐
│  前端：npm run dev（端口 8081） → 代理后端接口（http://localhost:8080/api） │
│  后端：./mvnw spring-boot:run（端口 8080） → 连接本地 MySQL 8.0          │
│  数据库：本地 MySQL 8.0（创建 ds 数据库，执行初始化脚本）                 │
└───────────────────────────────────────────────────────────────────────────┘
```

### 7.2 生产环境部署（容器化）
采用 Docker Compose 一键部署，包含前端、后端、数据库三个服务：
```yaml
# docker-compose.yml 核心结构
version: '3.8'
services:
  # 前端服务（Nginx 托管静态资源）
  frontend:
    build: ./web_data_structure
    ports:
      - "80:80"
    depends_on:
      - backend

  # 后端服务（Spring Boot 应用）
  backend:
    build: ./server_data_structure
    environment:
      - DB_URL=jdbc:mysql://db:3306/ds?serverTimezone=Asia/Shanghai
      - DB_USERNAME=root
      - DB_PASSWORD=00000000
    depends_on:
      - db

  # 数据库服务（MySQL 8.0）
  db:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=00000000
      - MYSQL_DATABASE=ds
    volumes:
      - mysql_data:/var/lib/mysql  # 数据持久化

volumes:
  mysql_data:
```

## 八、架构约束与风险
### 8.1 架构约束（必须遵守）
1. **模块边界约束**：禁止跨模块直接操作数据库（如评论模块禁止直接修改用户表），需通过对应模块的接口/服务调用；
2. **接口规范约束**：所有后端接口必须返回统一的 Result<T> 格式，前端统一通过 Axios 拦截器处理响应；
3. **安全约束**：用户密码必须加密存储，禁止明文传输；生产环境必须关闭 Swagger 文档或添加访问权限；
4. **性能约束**：单个接口响应时间≤300ms，列表接口必须支持分页（默认页大小≤20）。

### 8.2 核心风险与应对方案
| 风险类型         | 具体风险                                  | 应对方案                                                         |
|------------------|-------------------------------------------|------------------------------------------------------------------|
| 性能风险         | 可视化脚本加载慢、大列表渲染卡顿          | 按需加载脚本+预加载策略；长列表分页/懒渲染                       |
| 依赖风险         | AI 接口不可用、响应慢                      | 前端添加加载状态提示；支持切换 AI 模型；实现降级方案（仅文本答疑） |
| 数据风险         | 数据库压力大、数据丢失                    | 数据库索引优化；定期备份数据；生产环境启用数据库主从复制         |
| 兼容性风险       | 不同浏览器可视化效果不一致                | 前端适配主流浏览器；可视化脚本采用标准 JS API，避免依赖私有特性   |
